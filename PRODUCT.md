# PIMXNODE

<!-- impeccable:product-schema 1 -->

## Platform
web

## Product Purpose
Browser-to-browser file and text exchange between personal devices. Users open a shared room, approve incoming files and transfer without storing file contents on the signaling server.

## Users
People moving files between computers and phones; shared rooms support multiple recipients. This audience is inferred from the existing workflows.

## Capabilities and Constraints
The user approved a complete redesign, a custom logo, real three-dimensional motion, QR invitations, folder and batch transfers, queue controls, reconnect/resume, previews, text sharing, recipient approval, integrity verification, room controls, multiple recipients, local history, PWA and connection diagnostics. Keep React/TypeScript/Vite and the Node WebSocket signaling architecture. English and Persian, light and dark themes. File transfer supports arbitrary extensions; previews depend on browser codecs and supported renderers. TURN needs deployment credentials. Browsers must remain available during transfers. File contents never belong in analytics.

## Brand Commitments
Keep PIMXNODE. User wants an ambitious, distinctive animated redesign with natural language. Logo and visual direction are delegated by the user's instruction to implement the proposed work.

## Evidence on Hand
Existing runnable source, WebRTC transfer code, bilingual readmes and assets/readme. No verified customer claims, benchmarks or testimonials.

## Product Principles
Actual connection and transfer events drive the spatial presentation. Explain states in everyday language. Preserve arbitrary file bytes. Make each important operation accessible on phones and with the keyboard. Local history records metadata, not file contents.
